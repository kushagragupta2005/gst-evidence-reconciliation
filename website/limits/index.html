Limits & roadmap

Know what
is still unknown.

What remains untested before this prototype could support real work.

Current limits.

Synthetic recovery only.

Held-out tests share the same generator family. They do not demonstrate real taxpayer accuracy or causal independence of evidence families.

False positives and misses.

Honest factories can be flagged. Evasive cheats can remain below threshold or fire only one family. Alerts support human review; they are not findings of fraud.

Verification is generated.

Document status is synthetic metadata. A sophisticated-forger test remains unimplemented. A zero-event rule-of-three bound assumes independent factory outcomes.

Uncertainty gaps.

Ablation intervals, wrong-clear cluster-bootstrap intervals, paired before/after clearing metrics, and stock-aware/evasive comparisons remain unmeasured.

Scale is unfinished.

The large scale artifact is historical. The fresh comparison covers the current smaller dataset; DuckDB was faster. A new full-scale load and larger concurrency test remain pending.

Reproduction is local.

The author-machine fresh-clone run is documented at its original commit. A second-machine database reproduction and a fresh clone of this new presentation remain unverified.

The next useful steps.

  1. Challenge the verifier.

    Predeclare a sophisticated-forger scenario and measure wrong-clears with factory-aware uncertainty.

  2. Extend the measurement.

    Add ablation intervals, a regenerated low-prevalence evaluation and a stamped full-scale run under authorised loader access.

  3. Reproduce elsewhere.

    Run the documented setup on another machine and record every failure.

  4. Validate lawful data access.

    Start with tax-system evidence, then assess power and bank data access and privacy controls.

No operational deployment, working UDF or MCP demo is implied. Case data remain recorded; only guarded local follow-ups can run live.

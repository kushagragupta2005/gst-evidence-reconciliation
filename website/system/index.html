SQL does
the reconciliation.

V_FEATURES contains the per-check measurements. V_ALL_EVIDENCE retains rows above the threshold. V_RANKED_CASES groups source families into monthly priorities. V_SINGLE_SIGNAL_DISPOSITIONS explains single-family exceptions.

Window functions provide prior stock and operational baselines. The site does not claim a deployed Python UDF or an operational MCP integration; the demonstrated follow-up path uses guarded SELECT templates.

Access is
deliberately narrow.

Restricted reader.

The local API connects only through an account with session, schema usage and explicit SELECT grants on label-free views. It cannot read truth labels.

Guarded questions.

Only dispatch, timeline and evidence intents compile to fixed SELECT templates. Row limits, timeouts and rate limits bound the API.

Evidence-only notes.

A validator checks numeric claims against evidence rows. An optional LLM draft can be rejected. The recorded notes are the labeled deterministic fallback.

The workload.
The actual timings.

Workload timings on the author’s MacBook. Synthetic data. No general engine speed claim.

DuckDB was faster for both recorded checks. Its CSV loading is measured separately; Exasol ingestion was not remeasured. Different physical plans and execution environments limit the comparison.

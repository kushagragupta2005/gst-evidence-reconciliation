# Judge questions and short answers

1. **How is this different from invoice matching?** It checks whether declared transactions agree with separate physical and financial trails: power, stock, e-way bills, supplier returns and bank entries. Each case keeps the source rows for review.
2. **Why use synthetic data?** The project cannot use real taxpayer records. Synthetic scenarios make the planted truth known, so recall and false positives can be measured. They do not prove real-world accuracy.
3. **How did you avoid tuning to a target?** The threshold was selected on seed A by a fixed balanced-error rule, then frozen and evaluated on held-out seed B. No desired score was set.
4. **What are the held-out results?** On seed B, factory-month recall was 84.42% and the false-positive rate was 16.76%. At factory level, recall was 99.31% but the false-positive rate rose to 84.17%. These results rule out operational use.
5. **Why is the annual factory false-positive rate so high?** A factory is counted as flagged if any of its 12 months is flagged. Repeated opportunities to trigger a false alert accumulate across the year.
6. **Why require two independent signals?** Two different source families provide corroboration and keep a lone unusual measure out of the priority queue. Single-signal cases remain available for review; this reduces noise but also misses some cheats.
7. **How many cheats did the system miss?** It missed 629 active cheat factory-months, and five cheat factories were never caught. The report lists examples and the reason, including cases with only one signal above threshold.
8. **Does Exasol do more than store the CSVs?** Exasol runs the reconciliation and ranking views over the joined evidence. The stock roll-forward uses window functions; the full-scale run measured 20,978,945 raw evidence rows and retained per-view timings and query profiles.
9. **Why does this workload suit Exasol?** It repeatedly joins and aggregates large evidence tables across entities and months. In-memory columnar analytics lets the same database execute reconciliation, ranking and follow-up queries without exporting the working set to another analytics engine.
10. **Does the LLM decide who gets flagged?** No. SQL rules produce the ranking. The optional LLM receives evidence rows to draft a case note, and a validator checks numeric claims. The recorded demo uses the deterministic fallback because no API key is configured.
11. **Could an honest taxpayer be harmed by a false positive?** Yes. The measured false-positive rates are too high for enforcement use. The output is a review lead, not a fraud finding; a trained officer must inspect source evidence and context before action.
12. **What about real data and Germany?** No real taxpayer data is included. Power and bank records would need lawful access, privacy controls and validation on trusted cases. Germany is only a possible adaptation; this prototype does not implement German VAT rules or assert Germany-specific statistics.

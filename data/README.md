# Data layout and provenance

All project records are synthetic, generated by src/generate.py. There is no real taxpayer, power, bank, supplier or e-way API dataset.

- `metrics.json`: canonical public site metrics, built from committed result/report artifacts.
- `audit/`: exact compressed A/B/C feature exports and evaluator predictions, with hashes, to reproduce the current numeric audit from Git. Labels remain offline evaluator inputs; they are never read by the officer API.
- Local ignored `v3_a/`, `v3_b/`, `v3_c/`: generated raw tables and exported features. Seeds 51001/51002/51003; A calibrates, B/C evaluate frozen choices. `reports/dataset_inventory.json` lists every current table/header/count/hash and the scenario distributions.
- Other local `train/`, `seed_c/`, `v2_*`, `robust_*` and `full/`: historical/dev runs. These are not new V3 held-out or fresh full-scale evidence.

Generate raw C data with `.venv/bin/python -m src.generate --scale medium --seed 51003 --out data/v3_c --fake-explanations`. Loading is a separate, explicitly authorised operation; it recreates evidence tables. `make restore-audit` needs no database and validates hashes before writing CSVs. Full generated datasets, local wheels, credentials, DB images and venvs are intentionally not uploaded.
